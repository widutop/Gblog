# Gblog 主题制作指南

> 读者：会 PHP / HTML / CSS、想给 Gblog 做主题的人。不需要读核心源码。
> 版本：GBLOG_CORE_VERSION 1.4.0 · 2026-11

---

## 1. 三个前提

**① 一个主题 = 一个能独立渲染整站的完整包。** 页面模板（`template/`）、静态资源（`assets/`）全部随包携带，没有「基础包」可依赖。

**② 继承链只有两层：激活主题 → `theme.json` 里声明的父主题（可选）。** 任何文件都沿这条链查找，链上找不到就是不存在——**没有全局兜底**，缺模板就是缺页面，缺 CSS 就是缺样式。

- 做完整主题：`parent` 留空，包内必须有全量文件（复制官方 `default` 最稳）
- 做子主题：`parent` 指向完整主题，只放要覆盖的文件，其余继承父主题

**③ 数据用标签取，不要自己查库。** 标签是兼容承诺，数据库怎么改都不影响你的主题；自己写 SQL，升级就坏。

## 2. 目录结构

```
usr/themes/
├── default/                 # 官方默认主题（参考实现）
│   ├── theme.json           # 必需
│   ├── functions.php        # 钩子入口，可空
│   ├── screenshot.png       # 后台卡片封面，建议 720×450
│   ├── template/            # 页面模板 + 零件
│   │   ├── shell/           #   页架  header footer sidebar agg-sidebar
│   │   ├── index/           #   栏目模板  index index-stream index-software site-aggregate
│   │   ├── home/            #   栏目首页  home home-image home-music home-novel
│   │   ├── list/            #   分类页  list list-image list-music list-novel list-software
│   │   ├── single/          #   内容页  single single-image single-novel single-song single-software chapter
│   │   ├── page/            #   独立页面  page 404 search archive links tag post-card
│   │   └── parts/           #   零件（render_slot 调用，不进后台下拉）
│   └── assets/
│       ├── css/             # style.css(配色) base/layout/aggregate/cover-*/view/{类型}/...
│       ├── js/              # react.js player.js list_tabs.js 等
│       └── favicon.svg
└── mytheme/                 # ← 你的主题，结构同上
```

**目录名只是分类，不参与识别。** 上面的 `shell/ index/ home/ ...` 是官方分法，你可以改名、拆得更细、甚至全部放回 `template/` 根目录——**只要文件名不变**，前后台都照常认。识别规则只有一条：文件名（去 `.php`）＝模板 ID。

## 3. theme.json

```json
{
    "name": "我的主题",
    "slug": "mytheme",
    "author": "你的名字",
    "description": "一句话介绍（后台卡片显示）",
    "version": "1.0.0",
    "screenshot": "screenshot.png",
    "parent": "",
    "supports": ["sidebar", "dark-mode", "custom-css"]
}
```

| 字段 | 说明 |
|---|---|
| `name` / `description` / `version` | 后台「主题管理」卡片显示 |
| `screenshot` | 只写文件名；含 `..` 或绝对路径会被拒绝 |
| `parent` | 父主题目录名，目录存在才生效 |
| `supports` | 能力声明，仅用于卡片展示 |

## 4. 页面模板清单

模板只输出主体（`<section class="content">` 及内部），**不要写 `<html>`/`<head>`**——控制器已调用 `get_header()` / `get_footer()`。

文件头建议三行：

```php
<?php
/**
 * Template Name: 详情页·软件      ← 后台下拉显示的名字
 * View: detail                   ← 要进后台「页面模板」下拉才写（见第 9 节）
 * Context: $post, $site, $comments, $adjacent
 */
if (!defined('GBLOG_CORE')) { http_response_code(403); exit; }
?>
```

| 文件 | 页面 | 拿到的变量 |
|---|---|---|
| `index.php` | 全站聚合首页 | `$homePosts, $homeTabItems, $homeHeaderModules, $page, $totalPages` |
| `index-stream.php` / `index-software.php` | 聚合首页·混排 / 软件专题 | `$homePosts, $homeTabItems` |
| `site-aggregate.php` | 栏目聚合（Tab 列表） | `$posts, $site, $page, $totalPages, $gbTabItems, $gbPageBase` |
| `home.php` | 栏目首页（文章列表） | `$posts, $site, $page, $totalPages, $gbTabItems` |
| `home-music.php` / `home-novel.php` / `home-image.php` | 各类型栏目首页 | `$songs,$currentCat`（音乐）或 `$posts` + `$site,$page,$totalPages` |
| `list.php` | 分类列表（文章） | `$posts, $cat, $page, $totalPages, $gbTabItems` |
| `list-music.php` / `list-novel.php` / `list-image.php` / `list-software.php` | 各类型分类列表 | 同上；音乐为 `$songs,$currentCat` |
| `single.php` / `single-software.php` | 文章 / 软件详情 | `$post, $site, $comments, $adjacent` |
| `single-song.php` | 歌曲详情 | `$song, $related, $comments`（播放器变量 `$mp*`） |
| `single-novel.php` | 小说简介 | `$post, $novelBook, $novelChapters, $comments, $related` |
| `single-image.php` | 图片详情 | `$post, $site, $comments` |
| `chapter.php` | 小说章节（阅读器） | `$ch, $novel, $chapters, $prevCh, $nextCh, $bookUrl, $comments` |
| `page.php` | 通用单页（关于） | `$page_title, $page_heading, $page_html, $page_empty` |
| `links.php` | 友情链接 | `$links`（每项 `name/url/description`） |
| `archive.php` | 归档 | `$archives, $posts, $year, $month` |
| `tag.php` | 标签文章列表 | `$tag, $posts, $page, $totalPages` |
| `search.php` | 搜索结果 | `$q, $posts, $page, $totalPages, $total` |
| `404.php` | 404 | `$page_title, $message` |
| `header.php` / `footer.php` / `sidebar.php` / `agg-sidebar.php` | 页架 | 全局 |
| `post-card.php` | **单卡**（`post_card()` 用，不是页面模板） | `$item` |

没有 `category.php`（走 `list.php`）、没有 `comments.php`（评论是零件）。

**渲染入口只有两个**：

- `render_view($view, $vars)` —— 内容视图：`index|home|list|detail` 先看后台选版，再按类型专属，最后基础兜底；`page|404|links|archive|tag|search` 直接取同名模板。
- `render_slot($slot, $vars)` —— 取 `parts/{slot}.php` 并触发同名钩子。

变量用 `extract()` 注入，控制器 `get_defined_vars()` 全量传入。零件间传变量：`$__f = gblog_theme_part('xxx'); require $__f;`（保持同作用域）。

## 5. 零件清单（`template/parts/`）

零件不进后台下拉，只能被 `render_slot('名字')` 或 `gblog_theme_part('名字')` 调用。

**页架**：`head_shell`（`<head>` + `<body>` 的 data-* + 样式与脚本）、`navbar`、`main_open`、`footer_bar`、`modals`（登录/注册/找回密码）

**列表**：`post_card_list`（全站统一列表：tab 头 + 卡片 + 分页 + 空态，自带 `[data-gb-region]`）、`list_head`（tab 头）、`pagination`（全站唯一分页条）、`category_list`、`category_card_image`、`category_card_novel`

**详情**：`detail_body`（正文，文章/图片/软件共用）、`detail_title`、`detail_head`（下载卡插槽）、`download-box`（下载卡实体，三态判定）、`software-detail-head`（软件信息头）、`post-nav`（上下篇）、`related`（相关推荐）、`comments`（评论块唯一实现）

**音乐**：`music_player` `music_grid` `music_charts` `music_reel` `song_item` `song_chart_rows` `song_pagination` `player`

**小说**：`novel_chapter_list` `book_intro` `novel_book_extras` `work_card`

**其它**：`user_center`（用户中心整页）、`agg_layout`（聚合首页兜底版式）

规则：

- 评论块、分页条、下载卡、相关推荐、上下篇**各有唯一实现**，改这几个文件全站生效，不要复制出第二份；
- 卡片 `post_card_list` 的每条内容由 `page/post-card.php` 渲染，改它全站列表同步变；
- 零件内只能用入参或标签取数，不要假设控制器里还有别的变量。

**内容页三件套位置固定**：`post-nav` 紧贴发布信息下方 → `related` 在评论区正上方 → 评论块由控制器输出（小说简介页在 `book_intro` 内，章节页走左侧抽屉）。

## 6. 标签速查

规则：`the_*` 直接输出（已转义）、`get_*` 返回值、`is_*` 判断页面、`site_*` 当前栏目。

**页架**

| 标签 | 作用 |
|---|---|
| `get_header()` / `get_footer()` | 输出页头 / 页脚 |
| `get_sidebar()` | 输出侧栏（自动按页面选文章/音乐/聚合侧栏） |
| `render_slot('comments', $vars)` | 输出评论块（详情页用） |

**我在什么页面**

`is_home()` 全站首页 · `is_all_home()` 全站列表 · `is_site_home()` 栏目首页 · `is_single()` 任意详情 · `is_single_type('software')` 指定类型详情（article/software/song/image/novel） · `is_song()` · `is_novel_chapter()` · `is_category()` · `is_search()` · `is_user_center()` · `is_sidebar_off()` · `site_is_active('post')`

**单条内容**

| 标签 | 输出 |
|---|---|
| `the_title()` / `the_content()` / `the_excerpt(120)` | 标题 / 正文 HTML / 摘要 |
| `the_url()` / `the_cover()` | 详情链接 / 封面（无图返回空串，卡片已带占位样式） |
| `the_author()` / `the_date('Y-m-d')` / `the_category()` | 作者 / 日期 / 所属分类 |
| `the_views()` / `the_likes()` | 浏览量 / 点赞数 |
| `the_download()` / `get_download_info()` | 输出下载卡 / 返回下载信息数组（免费、需登录、扣金币三态由核心判定） |

**列表**

| 标签 | 作用 |
|---|---|
| `the_loop()` | 当前页内容数组，配 `foreach`；非信息流页面返回空数组 |
| `render_slot('pagination', [...])` | 统一分页条（见下） |
| `post_card($item)` | 输出一张标准内容卡（同 `page/post-card.php`） |
| `gblog_arclist([...])` | 任意位置取一小组内容（见下） |

分页零件调用：

```php
<?php render_slot('pagination', [
    'pgPage'  => $page,
    'pgPages' => $totalPages,
    'pgBase'  => 'index.php?do=category&id=' . (int)$cat['id'],
    'pgLabel' => '分页',
]); ?>
```

`pgBase` 不要带 `page=`、不要以 `?`/`&` 结尾（零件自己判断接什么）；只有 1 页时不输出内容；上一页/下一页始终占位，**不要用 CSS 隐藏**，否则首末页高度会跳。

**站点与设置**

`site_name()` / `site_url()` / `site_desc()` / `site_type()` · `the_site_name()` / `the_site_url()` / `the_site_desc()` · `gblog_opt('site_name', $默认)` · `gblog_opt_url($key)` · `current_site()`（原始数组）

**装配**

| 标签 | 作用 |
|---|---|
| `gblog_theme_part('xxx')` | 返回零件/模板真实路径（配 `require`，同作用域） |
| `gblog_tpl_path('xxx')` | 按模板 ID 取路径，不存在返回空串 |
| `gblog_theme_asset_url('assets/js/my.js')` | 主题内静态文件 URL（沿主题链查找） |
| `gblog_not_found('标题', '说明')` | 标准 404 输出 |

**取数：`gblog_arclist()`**

在任何模板/零件里取一小组内容（侧栏最新、页尾推荐、栏目热门），只回数据行，HTML 自己写：

```php
<?php foreach (gblog_arclist(['rule' => 'hot', 'limit' => 5]) as $row): ?>
  <a href="<?= e($row['url']) ?>"><?= e($row['title']) ?></a>
<?php endforeach; ?>
```

| 参数 | 取值 | 说明 |
|---|---|---|
| `limit` | 1–20（默认 6） | 超过 20 截断 |
| `rule` | `recent`（默认）/ `hot` / `recommend` / `ids` | 最新 / 浏览最多 / 排序优先 / 指定 ID |
| `zone` | `_home`（默认＝全站）或栏目 slug | 栏目不存在或未启用 → 返回空数组 |
| `source` | `auto`（默认）/ `posts` / `songs` | `auto`：音乐栏目取歌曲，其余取文章 |
| `ids` | `'12,15,20'` | 仅 `rule=ids`，最多 20 个，按给定顺序返回 |

别名：`row`→`limit`、`orderby`→`rule`、`typeid`→`zone`。

返回字段：`id`、`title`、`url`、`cover`、`meta`（文章＝栏目名 / 歌曲＝歌手）、`date`、`site_slug`、`site_type`。**不含正文和摘要**。

整页列表请走控制器的 `post_card_list`，不要用 `limit` 硬拉；要限定栏目传 `zone`，不要自己加 SQL。

## 7. CSS 契约

**加载顺序（固定，缺文件自动跳过）**

```
assets/css/base.css            布局重置
assets/css/style.css           配色（:root 变量写这里）
assets/css/aggregate.css       仅聚合首页
assets/css/layout.css          布局骨架
assets/css/cover-placeholder.css
assets/css/cover-fill.css      封面铺满（:where() 零特异性）
assets/css/view/{类型}/{视图}.css  类型专属（software/music/novel/image）
assets/css/user.css            仅用户中心
assets/css/soft-preview.css    存在才加载
assets/css/spacing.css         必须最后：全站零件间距唯一收口
```

完整主题包内这些文件都要有；子主题可在链上任意一层覆盖同名文件。

**变量（`:root` 必须全部定义，否则错色）**

```css
:root {
  --primary: …; --primary-dark: …; --primary-light: …;
  --bg: …; --bg-alt: …; --bg-card: …; --bg-elev: …; --card: …;
  --text: …; --text-muted: …; --border: …; --header-bg: …;
}
```

深色模式：`head_shell` 输出 `data-theme`，写 `[data-theme="dark"] { … }` 覆盖。

**静态资源路径**：一律 `gblog_theme_asset_url('assets/js/x.js')`。**不要自己拼 `?v=`**——该函数用 `is_file` 校验，带 `?` 必然返回空串；`.js` 的缓存参数它已自动追加。

**样式作用域**（`<body>` 上的属性）

```
data-site="post|soft|ganwu|..."    栏目 slug（同时是内容页 URL 前缀，管理员可改）
data-site-type="article|software|image|novel|song"   ← 按类型写样式用这个
data-view="home|list|detail|..."
data-home-mode="aggregate"
data-skin / data-layout            皮肤 / 版式
```

按内容类型写样式用 `body[data-site-type="software"]`，**不要按 slug 写**（同类型在不同站 slug 不同，且自建栏目 slug 由管理员自定义）。内容页 URL 前缀取 `sites.slug`：内置栏目是 `post/music/soft/image/novel`，自建栏目用自身 slug（如 `/ganwu-101.html`）；出链一律走 `gblog_content_url()` / `gblog_url()`，不要手拼。

**间距**：零件间距统一由 `assets/css/spacing.css` 的 `--gb-part-gap` 控制，不要在模板里写内联 `margin/gap`。

**无刷新 tab**：`assets/js/list_tabs.js` 拦截 `[data-gb-region]` 容器内的 `a.gb-list-tab` 与 `a.gb-page-btn`，`fetch` 整页后只替换该容器 `innerHTML` 并 `pushState`。

- tab 头和列表必须在同一个 `[data-gb-region]` 容器内；
- 一页只能有一个 `[data-gb-region]`（脚本取第一个）；
- tab 用 `a.gb-list-tab` + `is-active`，分页用 `pagination` 零件，不要自造 class。

## 8. 钩子（`functions.php`）

```php
<?php
add_action('head_meta', function () { /* </head> 前 */ });
add_action('body_start', function () { /* <body> 后 */ });
add_action('portal_top', function () { /* 聚合首页头部 */ });
add_action('before_content', function ($vars) { /* 正文前 */ });
add_action('after_content', function ($vars) { /* 正文后 */ });
add_action('agg_after_sections', function () { /* 聚合分区后 */ });
add_action('sidebar_widgets', function () { /* 侧栏模块后 */ });
add_action('footer', function () { /* 页脚 */ });

add_filter('layout_catalog', function (array $catalog) { return $catalog; });
```

过滤器：`layout_catalog` / `layout_file` / `download_link_target` / `route`。

让位机制（接管后核心不再输出）：`$GLOBALS['gblog_detail_title_taken'] = true` 接管详情标题、`$GLOBALS['gblog_comments_taken'] = true` 接管评论、`$GLOBALS['gblog_no_sidebar'] = true` 关闭侧栏。

## 9. 从零做一个主题

1. 复制 `usr/themes/default` → `usr/themes/mytheme`
2. 改 `theme.json`（`name`/`slug`/`version`，完整主题 `parent` 留空）
3. 改 `assets/css/style.css` 的 `:root` 变量与基础样式
4. 后台「主题管理」启用 → 全站换色完成

只改配色可以只做子主题：`theme.json`（`parent` 指向完整主题）+ `assets/css/style.css` 两个文件。

**删文件即回退**：子主题删掉覆盖文件就继承父主题；完整主题删掉就是真删（页面缺失）。

### 9.1 让模板出现在后台选版

后台「主题管理 → 选版」有两类下拉，判据不同：

**页面模板**（全局生效，存在 `page_template:{view}`）：文件头写 `View:`，或文件名以页面名开头。

| 页面 | `View:` 值 |
|---|---|
| 通用单页 | `page` |
| 404 | `404` |
| 友情链接 | `links` |
| 归档 | `archive` |
| 标签页 | `tag` |
| 搜索页 | `search` |

- 可多值：`View: search, tag` → 两个下拉都出现；
- 不写 `View:` 时按文件名推断（`search.php` / `search-*.php` → 搜索页）；
- 都不满足 → 不进任何下拉；
- `View:` 写错（如 `tags`）→ 整条声明作废且不降级，保存会被拒。

**栏目模板**（按栏目生效）：文件名必须是 `{前缀}-{名字}.php`，前缀决定进哪个下拉：

| 前缀 | 进哪个下拉 |
|---|---|
| `index-` | 栏目模板（聚合形态） |
| `home-` | 列表页 |
| `list-` | 分类页 |
| `single-` | 内容页 |

`home-grid.php` 会以「grid」出现在所有栏目的列表页下拉。页架件（`header`/`footer`/`sidebar`/`agg-sidebar`/`site-aggregate`）不出现在任何下拉。

**后台可以直接手填**，四种写法都认：版式 ID（`software_category`）、模板文件名（`list-software`）、文件头的 `Template Name`、下拉显示名。填错会逐条报错，不会静默失效；输入框下方灰字显示解析到的真实文件路径。

### 9.2 自查：这个文件会不会生效

| 文件 | 命中 | 结果 |
|---|---|---|
| `page/search.php` | 文件名＝页面名 | 进「搜索页」下拉，且是默认项 |
| `page/search-hot.php` | `search-*` 前缀 | 进「搜索页」下拉 |
| `page/tag-alpha.php` | 头写 `View: tag` | 进「标签页」下拉（声明优先） |
| `home/home-grid.php` | `home-` 前缀 | 进栏目「列表页」下拉 |
| `parts/x.php` | 在 `parts/` 里 | 扫描器不读，只能 `render_slot('x')` |
| `page/about-us.php` | 什么都不命中 | 未接入：补 `View: page` 或改名 |

## 10. 红线与已知约束

**红线（做了就会随升级失效）**

- ❌ `require` 核心目录（`core/`、`app/`、`admin/`）——只用标签
- ❌ 模板里写 SQL 查库
- ❌ 改动 `usr/uploads`、`usr/data` 下的内容
- ❌ 假设数据表字段名（字段不保证稳定）
- ❌ 模板不加 `if (!defined('GBLOG_CORE')) { http_response_code(403); exit; }` 守卫

**约束**

- 页面模板选版是**全局一份**，不区分栏目；栏目级选版只有 `index/home/list/single` 四种角色
- 选中某页面模板后，该页面不再回退默认模板，模板自己负责完整输出
- 主题不能通过「应用中心」上传（那里校验插件格式），直接放进 `usr/themes/`
- 主题模板 = 任意 PHP 执行、无沙箱：**只装你自己写的主题**
- 标签可归属栏目：`tags.site_id=0` 全站通用，`>0` 该栏目专属；做标签云用控制器给的 `$tags`
- 两套分页 class 并存：`.gb-pagination`（文章/软件/图片/小说）与 `.gb-song-pagination`（音乐），样式统一写到 `.gb-page-btn` 上最省事
- 改完样式没变化先强刷（Ctrl/Cmd + F5），CSS 带版本参数，多为浏览器缓存

**升级只覆盖** `core/`、`app/`、`admin/`、`install/`，`usr/themes/你的主题/` 永不触碰。
