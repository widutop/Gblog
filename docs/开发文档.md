# Gblog 开发维护手册

> 面向：维护核心代码的人。主题作者请读《Gblog-主题制作指南.md》。
> 版本：GBLOG_CORE_VERSION 1.4.0 · schema_version 12 · 2026-11

---

## 1. 环境与约定

| 项 | 值 |
|---|---|
| PHP | 8.0+（用了 `str_starts_with`），推荐 8.2 |
| 数据库 | MySQL 8 或 SQLite（`usr/data/gblog.sqlite`） |
| Web | nginx（`nginx.htaccess` 伪静态）+ php-fpm；Apache 用根 `.htaccess` |
| 常量 | `GBLOG_ROOT` / `GBLOG_CORE` / `GBLOG_CORE_VERSION` / `GBLOG_SCHEMA_VERSION` |

本地开发时按自己的环境调整 PHP / nginx 可执行文件路径。调试 curl 时可加 `--noproxy "*"` 绕过本机代理。

**全站路径铁律**：静态资源、表单 action、JS 接口、服务端 redirect 一律**根绝对**（`gblog_web_base()` + `gblog_root_absolute()`）。路径式 URL 会被浏览器当目录解析，相对地址会打错站点盘符外的地址，表现为整页掉样式。**不要用 `<base href>`**（会把 `#comments` 锚点解析到首页）。输出层 `gblog_rootify_relative_urls()` 兜底改写，后台地址统一用 `gblog_admin_url()`。

## 2. 目录地图

```
index.php            唯一入口
install.php          安装器（install/ 下是首装基线 SQL）
core/
├── bootstrap.php    只做加载清单 + 会话 + 时区（不放业务代码）
├── data/            db  migrate  content_blocks(gblog_arclist/gblog_query_items)
├── route/           permalink  context(page_context)
├── render/          theme  view  layout  template-tags  icons  music_theme  tags/
├── ext/             hooks  apps  agg_modules
├── auth/            security
└── lib/             settings posts comments users music backup links misc
app/                 控制器：content/ music/ novel/ user/
admin/               后台（多文件直连）
├── index.php login.php logout.php    入口三件套必须在根
├── content/ system/ account/         分组页面
└── inc/ assets/
usr/                 themes/ plugins/ uploads/ data/
_qa/                 回归测试（不进安装包）
```

**admin 分组不改变权限判定**：`gblog_admin_page_cap()` 用 `basename(SCRIPT_NAME)` 判权限，所以文件放进子目录不影响权限；但页内所有跳转/表单/静态资源必须走 `gblog_admin_url()`（相对路径会随目录深度打错）。

**core 加载顺序**：`lib/` 先（纯定义无副作用），再按 bootstrap 里的清单。新增文件记得加进清单，否则函数不存在。

## 3. 请求流程

```
index.php
└─ 归一 $_GET['do']（content.php 把 post→post、song→song）
   └─ app/{分区}/{文件}.php 控制器：只取数，不输出 HTML
      └─ render_view() / render_slot()
         └─ template/{角色目录}/{文件名}.php
```

- 入口层挂 `gblog_rewrite_hrefs()` 改写老模板里的 `index.php?do=`；
- 控制器只取数，新前台查询必须挂 `gblog_active_site_clause()` / `gblog_site_is_active()` / `gblog_music_site_active()`；
- `page_context()` 决定 `data-view` / layout 角色；**`app/content/content.php` 必须在 require 控制器前归一 `do`**，否则 `data-view=page`、版式选不到类型专属模板、详情页样式全丢。

## 4. 数据模型

22 张表：`ads apps categories coin_logs comments content_ids download_logs link_categories links novel_chapters password_resets post_reactions post_tags posts rate_limits security_logs settings sites songs tags users view_history`

要点：

- **posts / songs 共用全局 ID**：`gblog_next_content_id()` + `content_ids(seq)`，后台编辑显式 INSERT id；
- **内容表挂 `site_id`**：所有前台查询都要带栏目作用域；`sites` 表无 theme 列，全局主题在 `settings.current_theme`；
- **标签归属栏目**：`tags.site_id=0` 全站通用，`>0` 栏目专属；
- **评论按 `(target_type, target_id)` 挂载**：文章 `post`、歌曲 `song`，`post_id` 是历史列（歌曲写 0）；
- **迁移**：`core/data/migrate.php` 里 `GBLOG_SCHEMA_VERSION` 是唯一定义处，每次结构变更 +1 并写幂等迁移；首装基线 `install/schema.sql` 只是 v4 起点，装完必须 `gblog_migrate()` 补齐；
- **SQLite 兼容**：`RAND()`→`RANDOM()`、`DATE_SUB(NOW(),…)`→PHP 侧算时间、`ON DUPLICATE KEY UPDATE`→`save_setting()`。写 SQL 前先问「SQLite 有没有」。

**只有栏目（sites）保留 slug；文章 / 分类 / 标签一律按全局 id 定位（v12 起）**：
- 内容页 `?do=post&id=N`（关闭伪静态）/ 三形态 `.html`（开启后）；分类 `?do=category&id=N` → `/category-N.html`；标签 `?do=tag&id=N` → `/tag-N.html`；
- `posts/categories/tags` 的 `slug` 列已在 v12 迁移删除，`install/schema.*.sql` 不再建列；**禁止**在任何 SQL 里引用 `p.slug` / `c.slug` / `t.slug`，也不要恢复 `?do=post&slug=` 旧链接；
- 文章详情取数：`get_post_by_id($id, true)` 一次带回分类名 / 标签 / 歌曲（`$withDetail=false` 只做轻量存在性检查）；旧的「id→slug→get_post_by_slug()」两跳已废除；HTTP 200 不代表成功——**回归必须看响应字节、抓 Fatal**；
- 栏目 slug 的作用只有三个：内容页 URL 前缀、版式键 `layout:{role}:{slug}` 与自定义 CSS 键 `css:{slug}:{view}`、栏目页地址 `?do=site&slug=`。

## 5. 伪静态

`core/route/permalink.php` 三形态 + 开关（后台「功能开关」最下面）：

### 内容页前缀（= 栏目 slug）

| 形态 | 内置栏目 `post` | 自建栏目 `ganwu` |
|---|---|---|
| s1 | `/post/101.html` | `/ganwu/101.html` |
| s2 | `/post/20261114101.html` | `/ganwu/20261114101.html`（8 位 Ymd 拼 id） |
| s3 | `/post-101.html` | `/ganwu-101.html` |

- **内容页前缀 = 所属栏目 `sites.slug`**。5 个内置栏目 slug 恰是 `post/music/soft/image/novel`，与旧 type 前缀完全一致，所以改造对老链接零影响；自建栏目直接用自身 slug。
- **链接必须按内容真实归属生成**：列表行常常只有 id，由 `gblog_content_meta_by_id()` 反查 `type + 栏目slug + created_at`（`gblog_song_fields_by_id()` 同理）；反查都要带 `s.slug AS site_slug`，漏一处就会退回 `post-` 前缀。
- **slug 必须能直接进 rewrite**：`gblog_site_slug_is_url_safe()` 要求 `[a-zA-Z0-9][a-zA-Z0-9_-]*`，并排除 `column/category/tag/chapter/novel-数字` 及 `index/admin/usr/core/app/install` 等保留名（否则被专用规则抢走）；后台保存时会拦，URL 生成层另有兜底回退 `gblog_type_prefix($type)`，中文 slug 不会产出坏链。
- **前缀不参与归属校验**：id 全局唯一，改栏目 slug 后旧链接仍要能访问；canonical 自动指向新前缀，301 只归一前导零 id，不强跳（避免打断外链/收藏夹）。
- 栏目**首页**地址 = 栏目 slug（用户可控）：`/{栏目slug}.html`；内置栏目 slug 与 type 前缀同名，自然得到 `/post.html` 等缩写页。两种情况回退旧约定（type 第一个栏目用缩写页、其它用 `/column-N.html`）：a) slug 不安全（中文/保留名/纯数字）；b) slug 恰为 type 前缀但本栏目不是该 type 第一个启用栏目（rewrite 的 `/前缀.html` 固定指向第一个栏目，避免错位）。rewrite 末尾有通用规则 `^/([a-zA-Z0-9][a-zA-Z0-9_-]*)\.html$ → do=site&slug=$1` 承接（nginx/Apache 双份同款，必须排在专用规则与老链接兜底之后）；未知 slug 由 site.php 返回 404 皮肤页。
- 章节页 = `/novel-{作品id}-{本书内第几章}.html`，「第几章」是已发布章节 `ORDER BY sort_order ASC, id ASC` 的位置（从 1 起），出链层与控制器排序口径必须一致；章节前缀固定 `novel`（rewrite 专用规则硬编码），不随栏目 slug 变。
- 非内容页一律顶级 `.html`：`post.html`、`column-N.html`、`category-N.html`、`tag-N.html`、`about/links/archive/search/songs.html`；
- 服务端规则：`nginx.htaccess` 专用规则在前、通用兜底在后，内容页通用规则前缀为 `([a-zA-Z0-9_-]+)`（**不是** type 枚举），**同时认三形态、任意 slug 与 `?do=`**；nginx 配置里**禁写 `{n}` 量词**（花括号会被当配置块）；
- Apache 主机：包内按设计不含根 `.htaccess`（避免覆盖主机商含 AddHandler 的文件导致 503）。随包分发 `install/apache-htaccess.txt`（含防护与等价重写），**安装器装完自动落盘**：根目录无 `.htaccess` 则整份写入，已有则检测行首 `# GBLOG-REWRITE-BLOCK-START` 标记、无则**追加**（禁覆盖）；写入失败在完成页提示手工合并，补丁包另带包根 `Apache-伪静态规则（可选上传）.txt`（与 install/ 内同源）；
- 改完 nginx rewrite 必须 `nginx -t` + `-s reload`；`include nginx.htaccess` 必须在 **server 级**，放 `location /` 内会被 `location ~ \.php` 压过导致 `/usr/data/*` 泄露。

## 6. 后台

- 侧栏菜单在 `admin/inc/header.php`，页面按 `content/ system/ account/` 分组；
- 选版页 `admin/inc/sections/layout.php`：每个格子是「下拉 + 手填」，后端 `gblog_layout_id_from_input()` / `gblog_page_template_from_input()` 接受版式 ID / 文件名 / `Template Name` / 下拉名，认不出必须进 `$lbad/$pbad` 报错，**禁静默丢弃**；
- 干净安装不写 `layout:*`：`gblog_layout_default()` 在设置为空时按 `sites.type` 套 `gblog_layout_recommended()`（仅 home/list/detail，`_home` 与 aggregate 不兜底）；否则歌曲/软件/小说列表会掉版式、显示「该栏目暂无内容」；
- 后台只留操作，不写教程文案；
- 登录带 CSRF；改密码三处都要调 `gblog_reset_token_invalidate_user()`。

## 7. 主题与模板

细节见《主题制作指南》。核心只记三条：

1. `gblog_tpl_index()` 递归扫 `template/**/*.php`，**键＝文件名**＝模板 ID，目录名不参与识别；`parts/` 标 `part=true` 不进模板清单；
2. 查找一律 `gblog_tpl_path($id)`，**禁再 `scandir` 一层或硬拼 `template/{name}.php`**；
3. 主题目录叫 `default`；`home_mode=aggregate`、layout 的 `aggregate` 角色键、`site-aggregate.php`、`aggregate.css` 指的是「聚合形态」，**与主题名无关，不要一起改**。改主题目录名要同步 migrate 与 4 处默认值。

## 8. 备份与运维

- 备份目录：`gblog_backup_dir()` = `站点根/usr/data/backups`（站点内、随站迁移）；`nginx.htaccess` 的 `location ^~ /usr/data/` 整目录 403，目录内还有 `.htaccess`/`web.config` 兜底；
- 不可写时回退：`上级/gblog_backups/{站点名}` → `上级/gblog_backups` → 系统临时目录；
- 完整备份 = 数据库 + `usr/uploads/**` 打包 zip；恢复只接受本站签名（`GBLOG_SECRET`），跨站/无签名必须用一次性恢复码；
- 换密钥/换站恢复前先备份；`gblog_known_tables()` 必须与 `SHOW TABLES` 同步（漏表会导致整份备份恢复失败）。
- 数据清理：`db_clean(true)`（「清理全部」）只删 `is_builtin=0` 的自建栏目，随后 `gblog_restore_builtin_sites()` 幂等补回 5 个内置栏目；**内置栏目是站点骨架，任何清理都不能删**（曾无条件 `DELETE FROM sites` 导致整站无栏目）。

## 9. 常见故障

| 现象 | 先查 |
|---|---|
| 全站 404 / 153B 空响应 | php-cgi 9003 是否活着 |
| 整页没样式 | 资源是不是根绝对；主题 `theme.php` 的 `$ver` 是否递增 |
| 详情页格式全丢、版式不对 | `$_GET['do']` 归一是否漏了（`data-view` 变 page） |
| 首页掉字节、页头整块消失 | `gblog_theme_part()` / `gblog_tpl_path()` 是否命中；插件是否加载 |
| 页面 200 但内容空白 | 抓响应体看 Fatal（`display_errors` 关闭时状态码仍是 200） |
| 上下篇串栏目 | `get_adjacent_posts()` 是否显式传 `$site_id`，`$GLOBALS['site']` 是否先设置 |
| 备份列表有、目录里没有 | 看后台卡片上的「服务器备份目录」真实路径 |

## 10. 发布与回归

1. `php -l` 全量语法检查
2. `php _qa/run.php`（只读）/ `--admin-user= --admin-pass=`（含后台）；测其它库时先改 `_qa/config.php` 的 `base` / `db`，SQLite 下断言已兼容
3. 前台逐页抓字节 + 抓 Fatal（首页 ~92KB）
4. 打包：`python _pack_gblog.py` → `Gblog-clean-install.zip`，断言全 PASS
5. 改 PHP/模板后必须重打包；改 CSS/模板后必须递增 `core/render/theme.php` 里的 `$ver`
6. `_qa/suite/.integrity_baseline.json` 是文件指纹基线，改动后删掉重跑即重建
